# `ui.overlay` / `ui.cursor` — 浮かせるものを C 側へ寄せる

IME の preedit と候補、補完リスト、ツールチップのような「本文の上に一時的に
浮かべる小さな窓」と、**テキストカーソル**を、アプリごとの実装から C 側の
共通機構へ移す計画。どちらも「アプリは座標だけ渡す」形にする。

現状の唯一の実装は [`examples/skk_test.js`](../examples/skk_test.js) の
`imeFloatDraw()` で、この文書はそれを1件目の移行対象として書いている。

## 1. なぜ共通化するのか

`skk_test.js` のフロート実装は約60行あるが、**IME 固有なのは「preedit と候補を
並べる」ところだけ**で、残りはどのアプリでも同じになる。

| 処理 | 性質 |
|---|---|
| カーソルの画面座標を出す | **アプリ固有** |
| 箱を画面内にクランプ | 共通 |
| 下端に当たったら上へ返す | 共通 |
| オンスクリーンキーボードの予約高さを避ける | 共通 |
| **覆った領域の復元 (damage)** | 共通、**かつ最も間違えやすい** |
| 選択項目の反転、はみ出しの省略 | 共通 |

**damage が本当の動機。** `ui.cells` に直接描く方式では、アプリが「フロートが
覆った行」を記録して次の描画で引き直させるしかない。`skk_test.js` の
`dirtyRows` がそれで、**同じ仕組みを忘れたせいでカーソルが古い位置に残り続ける
バグを実際に出した** (実機報告 2026-07-29: 水色の下線が複数残る)。差分描画は
行の内容だけを署名にするので、内容の変わらない行への上描きは永久に残る。

これはアプリごとに再実装させてはいけない種類の処理で、しかも
「たまに1フレーム残像が出る」形で失敗するため気づきにくい。

## 2. 置き場所: ui_tab5 の LVGL オブジェクト

3案を検討した。

| 案 | 判定 |
|---|---|
| JS 共有ライブラリ | **不可**。mqjs にモジュール機構が無く (`require`/`import`/`eval` いずれも無し)、実体はアプリへのコピペになる。「ライブラリに見えるコピペ」は片方だけ直したときに気づけないぶんローカルなコピペより危険 |
| キャンバスに描く C プリミティブ | 可能だが、覆った矩形の保存/復元バッファを自前で持つことになる — LVGL が既にやっていることの再実装 |
| **LVGL オブジェクト (採用)** | アプリのキャンバスに一切触れないので **damage が構造的に消える**。`bodyDraw` の差分描画は無改造のまま成立し、`dirtyRows` 相当の記帳が全アプリから不要になる |

**副次的だが大きい利点: フォント。** LVGL 経路は `ui_font()`
(Noto JP = かな87 + カナ90 + 漢字3,517) を使うので、**S3/S4 の端末フォント
作業を待たずに IME 窓が読める**。`ui.cells` のグリッドを通らないため。

## 3. API

IME 専用にはしない。`skk.float()` のような形は ui と skk を結合させ、補完
リスト・ツールチップ・カラーピッカーに転用できなくなるうえ、skk_core が
依存ゼロである設計 (§3 of `skk-ime-design.md`) を壊す。

```js
ui.overlay(id, spec)   // 生成 / 更新
ui.overlay(id, null)   // 隠す
```

```js
ui.overlay(0, {
    /* アンカー = カーソル。グリッドアプリは col/row をそのまま渡せる。
       skk_test のように可変幅 (ui.text) で描く行があるアプリは x/y/h。
       両方与えられたら x/y/h を優先する。 */
    col: 12, row: 5,
    x: 240, y: 120, h: 24,

    place: "auto",                  // auto | below | above
    lines: ["▽かんじ"],             // 縦に積むテキスト行
    items: ["漢字", "感じ", "幹事"], // 横並びのチップ列 (省略可)
    sel:   0,                       // 反転させるチップ。-1 = なし
    dir:   "h"                      // チップの並び。"v" で縦 = 補完リスト
});
```

要素は **`lines` と `items` の2種類だけ**にする。`lines` が preedit、`items` が
候補。TAB 補完の縦リストは `dir: "v"` で同じ機構に乗る。

### 枠組みが持つ配置規則

- 左右のクランプ
- 下端および**オンスクリーンキーボードの予約高さ**に当たったら上へ反転
- ステータス行とヒント行は覆わない
- **可能な限りアンカーの桁を保つ** — 視線を動かさないことが目的なので、
  クランプで横にずらすのは最後の手段

### ライフサイクル

ハンドルはアプリあたり4本程度。既存の ssh セッションや widget と同じく
**アプリ停止時に自動解放**する。停止したアプリのフロートが画面に残るのは
最悪の失敗なので、ここは既存のハンドル管理に必ず合わせる。

## 4. アプリ側に残るもの

**アンカー座標だけ。** これは本質的にアプリ固有で、C から知る方法がない
(ssh_vt は端末グリッド、skk_test は折り返し + cells/text 混在、エディタは
独自スクロール)。グリッドアプリは `col/row` を渡すだけで済む。

移行後の `skk_test.js` は `imeFloatDraw()` 約60行と `dirtyRows` のフロート分が
消えて、こうなる:

```js
if (st & (skk.PREEDIT | skk.CANDS | skk.SEL)) {
    var xy = cursorXY();
    ui.overlay(0, { x: xy[0], y: (BODY_TOP + xy[1]) * LH, h: LH,
                    lines: [skk.preedit(ime)],
                    items: cands, sel: candSel });
} else if (st & skk.COMMIT) {
    ui.overlay(0, null);
}
```

## 4.1 `ui.cursor` — カーソルも同じ層に寄せる

オーバーレイと同じ理由が、テキストカーソルにもそのまま当てはまる。むしろ
**カーソルのほうが動機が強い**。

**点滅が JS ワーカーを起こし続けている。** 現状 `skk_test.js` は 530 ms の
`setInterval` で点滅させており、1 回ごとに JS を起こし → イベントキューを
通し → `bodyDraw` が TROWS 行ぶんの署名比較を回し → 1 行引き直す、を
2 px の矩形を反転させるためだけにやる。これがカーソルを持つ全アプリで恒久的に
走る。C (UI タスク) 側なら LVGL オブジェクトの hidden を反転させるだけで
**JS の関与がゼロ**になる。

**整合性の問題もある。** オーバーレイを LVGL にするなら、キャンバスに描いた
カーソルの上に LVGL のフロートが乗る形になり、Z 順とタイミングの管理が
2 つの層に分かれる。両方 LVGL なら 1 箇所で済む。

```js
ui.cursor({ col: 12, row: 5 });                    // グリッドアプリ
ui.cursor({ x: 240, y: 120, h: 24 });              // 可変幅アプリ
ui.cursor({ x, y, h, style: "bar", blink: true }); // 既定は bar / 点滅あり
ui.cursor(null);                                   // 隠す
```

アンカーの型とクランプ処理は `ui.overlay` と共有する。

**点滅の位相リセットに専用 API は要らない。** アプリは打鍵のたびにどのみち
位置を更新するので、**`ui.cursor()` の呼び出し自体を「点灯にリセット」の
合図**にする (座標が同じでも呼べば点灯から始まる)。いま JS 側にある
`blinkOn = true` はこれで消える。

**副作用として得なこと:** 背景に回ったアプリのカーソルを C が自動で隠せる。
現状はキャンバスに残ったままで、アプリが気をつけるしかない。

### ⚠️ この方式で作れないもの: 反転ブロックカーソル

**下の文字を反転させるブロックカーソルは作れない。** LVGL のオーバーレイは
キャンバスのピクセルを読めないため。`bar` / `underline` / 半透明の `block` は
出せるが、端末らしい反転ブロックが要る場合はアプリがキャンバスに描くしかない。

したがって **`ui.cursor` は必須ではなく任意**とし、アプリが自前で描く道を
残す。`ssh_vt` は端末忠実性のために反転ブロックを選ぶ可能性がある。

## 5. 実装手順

| # | 内容 | 実機 | 検証 |
|---|---|---|---|
| **O1** | `ui_tab5` に LVGL オーバーレイ層 (非表示の container を4つ、`ui_font()`)、`UI_CMD_OVERLAY` と `ui_post` 経路 | 要 | 固定座標に出す最小の呼び出しで、キャンバスの再描画に影響しないこと |
| **O2** | 配置規則 (クランプ / 上下反転 / キーボード回避 / 桁の保持) | 要 | 画面四隅とキーボード表示・非表示の両方でアンカーを動かす |
| **O3** | `lines` / `items` / `sel` / `dir` の描画 | 要 | 長い候補列がはみ出したときの省略、`dir:"v"` の縦リスト |
| **O4** | JS バインディング `ui.overlay()` + ROM 再生成 | 要 | `gen/device_stdlib.h` と `gen_pc/` の両方 |
| **O5** | ハンドルのライフサイクル (アプリ停止・背景化で自動解放/非表示、二重 close) | 要 | アプリを停止してフロートが消えること |
| **O6** | `ui.cursor()` — アンカーとクランプを O2 と共有、点滅は UI タスクのタイマー、更新呼び出しで位相リセット | 要 | 点滅中に JS が起きないこと (打鍵していない間の JS 側 CPU) |
| **O7** | `skk_test.js` を移行し、`imeFloatDraw()`・点滅の `setInterval`・`dirtyRows` を削除 | 要 | 見た目が現状と同等かそれ以上、残像なし |
| O8 | `ssh_vt.js` に IME を載せるときの2件目の利用者 | 要 | S5 の作業と合わせて。反転ブロックカーソルが要るなら `ui.cursor` は使わず自前で描く (§4.1) |

**O7 まで通って初めて価値が出る。** O1〜O6 だけでは利用者がゼロで、
「動くが誰も使っていない層」を1つ増やしただけになる。

O6 の検証は見た目ではなく **JS 側の CPU** で見る。打鍵していない間、点滅の
ためだけに JS が起きていないことが目的なので、IME の計測 (今の `ui.imeStats()`) ではなく
`sys.heap()` を回している既存の 1 秒タイマー以外に JS の実行が無いことを
確認する。

## 6. コスト

打鍵あたり `lv_label_set_text` + 位置更新で、LVGL は変化した矩形だけを
無効化する。現状 (キャンバスの2行を引き直す) とほぼ同等だが、**damage が
正しく、アプリ側の記帳がゼロ**になる。

`ui.*` はコマンドをキューへ積むだけで実際の描画は UI タスクがやる、という
既存の非同期モデルはそのまま。`ui.keyboard()` と同じ扱いになる。

## 7. やらないこと

- **`skk.float(h, ...)`** — 実装は最小になるが ui と skk が結合する。
  補完・ツールチップ・カラーピッカーに転用できなくなる
- **キャンバスへの save/restore 方式** — LVGL が既にやっていることの再実装
- **アプリにアンカー以外を計算させる** — それが重複している当のもの
